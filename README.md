# Haihong Presales Hub

海弘售前协同管理系统。当前仓库同时保留需求、低保真原型和正式应用，三者边界如下：

| 内容 | 位置 | 说明 |
|---|---|---|
| 需求规格 | `docs/requirements-zh-CN.md` | 当前基线为 v0.13 |
| 低保真原型 | 根目录 `index.html`、`styles.css`、`app.js` | 仅浏览器模拟状态，不连接正式数据库，不作为业务逻辑 |
| 正式前端 | `web/` | 只通过服务端 API 读取和修改数据 |
| 正式服务端 | `server/` | 身份认证、数据权限、报价金额、审批、合同生成与归档的唯一可信入口 |
| 自动化测试 | `tests/` | 全部使用运行时生成的虚构数据和随机测试密码 |

## 当前技术方案

- Node.js 单体服务，Express 提供 API 和静态页面。
- SQLite 保存业务数据，启用外键与 WAL；适合 5 名售前和少量审批人的单实例初期规模。
- 密码使用 `scrypt` 加随机盐保存，登录使用服务端会话、HttpOnly + SameSite Cookie 和 CSRF Token。
- 金额统一使用整数“分”，数量使用千分单位；前端传入的金额会在服务端复算。
- Excel 与 Word 使用轻量的 OOXML 组件解析和生成，不接入外部云存储或付费消息通道。
- 上传文件保存在公司控制的服务器 `storage/`，使用随机存储名、SHA-256、实体权限校验和下载审计。
- SQLite 与被引用归档文件按同一批次备份；恢复只允许写入全新隔离目录，不提供覆盖正式库的页面或命令。

## 本地运行

要求 Node.js 22.13.0 或更高版本。

报价使用标准 Word 模板制作后导出 PDF，仅上传 PDF 作为检查、预览和审批的正式文件。上传时自动检查客户、日期、开户行、账号、报价人、电话和邮箱，并核对可识别的客户及含税总额；明确不一致或固定字段无法确认时提示修改。总额无法识别时允许上传和送审，页面和审批记录标明“金额未核对”。主报价以报价人邮箱为结束位置，历史 Word 源文件、报价及审批记录保留；报价单的 Word 导出已关闭，标准模板下载继续保留。

```powershell
npm.cmd install
Copy-Item .env.example .env
```

编辑 `.env` 中的运行参数。首次创建管理员时，在终端提供用户名和显示名称，并按提示隐式输入两次密码：

```powershell
npm.cmd run init-admin -- --username admin --display-name "系统管理员"
```

密码至少 12 位，输入过程不回显，也不会写入 `.env`、命令参数或日志。管理员创建成功后启动：

```powershell
npm.cmd start
```

默认访问 `http://127.0.0.1:4173/`。正式外网部署必须由反向代理提供 HTTPS，只向公网开放 443，并设置 `HH_SECURE_COOKIE=true`。

2026-10-14 当前电脑的实际初始化、合同模板发布、备份恢复和 HTTP 验证结果见 [本机部署记录](docs/local-deployment-2026-10-14-zh-CN.md)。当前只监听本机回环地址；不要把该状态表述为已完成外网发布。

生产服务器还应配置独立于 `data/` 和 `storage/` 的 `HH_BACKUP_PATH`。服务启动后默认按服务器本地时间每日 02:00 自动备份，可用 `HH_BACKUP_HOUR=0` 至 `23` 调整。升级前手工备份：

```powershell
npm.cmd run backup -- --reason "升级前手工备份"
```

恢复命令仅用于服务器本地的离线隔离演练，目标必须是全新或空目录，绝不会覆盖正式数据库、正式 `storage/` 或备份源：

```powershell
npm.cmd run backup:restore-drill -- --batch "D:\HaihongBackups\backup-批次号" --target "D:\HaihongRestoreDrills\本次演练目录"
```

系统不自动删除历史批次。运维人员须监控备份磁盘剩余容量，并记录升级前备份批次号和 CLI 输出的校验结果。详细目录结构和校验规则见开发说明。

管理员登录后，应先创建综合部经理、研发经理和审批领导，再把售前账号关联到直属综合部经理；系统不提供默认账号或演示密码。
