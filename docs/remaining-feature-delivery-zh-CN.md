## 2. 第十六批：通用附件

已完成客户、已保存跟进、调研整体及单题、报价草稿的正式页面入口和服务端闭环。新文件按不可变版本归档；调研完成和报价提交锁定精确版本及摘要；转让后原负责人立即失权；受控删除不清除历史字节；旧库升级、备份和隔离恢复均覆盖通用附件。项目全量自动化 147/147 通过。当前未宣称浏览器视觉验收或病毒查杀已完成。

对应需求 7.4、7.7、7.8、7.11、7.13。优先覆盖客户、跟进、调研及问题答案、报价的上传、历史版本、权限下载和受控删除；合同沿用已有三类正式归档及不可覆盖门禁，不以通用上传绕过正式模板或附件一价格明细的校验。

实施要求：

- 使用已有本地文件归档方式，保存原文件名、上传人、时间、业务对象、摘要和版本；新文件不覆盖原文件。
- 文件类型、大小、签名和真实业务归属由服务端校验，不信任浏览器给出的客户或业务对象 ID。禁止执行类文件；未接入病毒扫描时不得宣称文件已查毒。
- 售前写入限本人当前客户，管理员按现有管理权限操作；领导的查看和审批不自动取得修改附件权。转让后原负责人对历史版本也立即失权。
- 调研确认版、已提交报价及终审快照不可因后续附件变化被改写。报价提交/审批快照应锁定被引用附件的版本与摘要，不能继续保留空附件占位或只引用会变化的“最新版”。
- 副总仅可从有权报价及其固定快照读取相应附件，不因此取得客户全部通用资料。
- 删除与替换均重新鉴权并留痕；被锁定版本/审批快照引用的文件及已签订合同不得删除。保留不可覆盖的原文件和来源，先完成受控业务删除，不擅自增加自动物理清理或保留周期。
- 新增文件引用须纳入已有同批备份与恢复校验；旧库迁移须可重复执行，不能丢失原文件记录和下载权限。

验收必须覆盖正常操作、非法文件、跨客户伪造 ID、转让/停用失权、重复上传或点击、替换与审批竞争、被引用附件删除拒绝，以及备份后隔离恢复和 Word 导出权限。新上传能力必须有真实可用入口，不以文件表或单一服务函数代替交付。

## 3. 长表单自动保存

已完成需求 10.1 中首期需要的现有调研、报价和合同草稿自动保存。复用正式草稿保存逻辑，没有为五人团队引入独立协作编辑平台。

- 显示“未保存 / 保存中 / 已保存 / 保存失败”及最后成功时间；未保存内容离页前明确提醒。
- 保存只作用于当前可编辑草稿，服务端每次检查权限、状态和版本。不能自动完成调研、提交/通过报价、生成合同、勾选合同人工确认或创建确认版的后继版本。
- 自动请求与手动保存、确认、审批提交之间应有顺序和版本保护；旧请求不得覆盖新内容，双击和网络重试不得制造重复业务动作。
- 对不完整或不合法字段明确显示尚未保存的内容，不得在请求失败后仍显示“已保存”。断网、会话失效、负责人转让、其他页面更改状态时停止写入并提供可理解的处理提示。
- 不把密码、会话凭据或整份客户资料存入未鉴权可读取的浏览器持久缓存。重新打开草稿时仍以当前服务端权限为准。

专项及完整回归证明服务端版本令牌、失败待保存、旧页面覆盖阻断、审批边界和合同人工确认边界有效；全量自动化 152/152。浏览器断网模拟和正式访问地址下的点击验收仍归 UAT。
