# 主报价单检查功能说明

> 现行流程：仅上传 PDF，不再上传 Word 源文件；历史文件与审批记录保留。上传 PDF 时自动检查客户、日期、开户行、账号、报价人、报价人电话和邮箱是否填写，并核对可识别的客户与含税总额。明确不一致或必填字段无法确认时直接提示；金额无法识别时允许上传和送审，但页面及审批快照标明“金额未核对”。不再要求手动发起检查，也不展示通过后的检查结果。查看和审批使用同一 PDF 预览并保留审批记录；需要修改时在本地修改后重新上传。

> 客户与金额校验更新：选择 PDF 后，系统在保存前从主报价中识别客户名称和最终含税总额，与所选客户全称或已维护简称、登记金额比较。确认不一致或客户无法识别时不保存也不允许送审；金额无法可靠识别时允许继续并提示“金额未核对”。历史未发送报价会在查看和送审时重新核对，既有文件与审批快照不改动。PDF 使用本机依赖在页面内分页渲染；浏览器页面视觉效果仍需在实际使用环境验收。

> 2026-11-03 的历史方案曾允许附加 Word 源文件，此入口已于 2026-11-09 取消，已有文件继续保留。下文的旧 Word 上传方案仅供追溯。报价人邮箱行以后作为附件范围，不做业务校核。PDF 提取和格式判断有局限；扫描件或加密件不能用于自动检查。报价 Word 导出及未审批预览导出接口均已关闭。

本功能用于对上传的报价原文件进行主报价检查。根据 2026-11-02 的确认，新上传及替换的报价原文件和报价附件仅接受 Word（DOCX）；PDF、Excel、旧版 DOC 及其他格式不支持。旧版 DOC 需要在 Word / WPS 中另存为 DOCX，直接改扩展名不能通过内容校验。网页新建报价入口已隐藏，原编辑代码、历史报价和审批记录保留。需求讨论时的规则草案保留在 `docs/quote-main-document-review-rules-zh-CN.md`；其中“未开发”和 Excel 范围反映草案创建时的状态。

## 使用方式

在“报价管理”点击“下载标准模板”，用 Word / WPS 替换双花括号中的字段并填写表格。不优惠时删除“优惠后合计”行。模板由运维按 [外网部署交接](external-deployment-handoff-zh-CN.md) 安装公司现用 Word 原件，应用按原字节提供下载。

1. 在“报价管理”中上传已有 Word（DOCX）报价，关联客户并登记含税总额。
2. 在报价列表或发送审批页面选择“检查主报价”。系统结合商务条款及报价人信息，建议以报价人邮箱所在位置结束；售前需要核对位置，必要时手动选择。
3. 系统仅检查选定范围内的主报价。页面区分“需修改”和“人工核对”，提供可定位的段落、表格或单元格位置。附件不参与金额、文字、单位或格式校核。
4. 对明确错误在本地修改原文件后重新上传并检查；人工核对项目由提交人确认。审核通过后原文件仍可下载。
5. 发送审批时，检查结果、结束位置、文件版本摘要、确认人及时间与本次审批快照一同保留。文件、金额或客户负责人发生变化后需重新检查；退回或调整价格产生的新版本也需重新检查。

## 自动检查与人工核对边界

- 可识别标准字段时，检查报价单位、客户名称、编号、日期、有效期、商务信息、报价人及联系方式；客户联系人和客户手机不设为必填。开户行与账号比对现有公司资料，差异需人工核对。
- 标准模板的客户、编号、日期、金额大写和报价人信息如果仍保留对应的中文占位符，将提示填写；客户联系人和客户手机仍非必填，可以删去占位符后留空。
- 表头及数据行可可靠识别时，检查单位、数量、含税金额、合计、主报价与费用明细的合计、最终报价及人民币大写；对未税单价、税率和常见舍入差异提供辅助核对。
- 允许表格行列变动和合并拆分。若复杂合并、拆分表格、多处合计或计价方式无法可靠识别，列为人工核对，不宣称检查通过。
- 能识别部分固定标题字体、字号和表头底色；公司 Logo、完整排版、分页、遮挡、全部错别字和专有名词仍须人工核对。已实现少量常见错字提示，不代表通用中文语义纠错。
- Excel 公式使用文件中保存的缓存结果，系统不重新计算公式；公式结果始终提示人工核对。报价原文件中的金额不会被系统自动修改。
- 历史 Excel 文件及既有解析、预览和导出兼容代码保留，不删除旧文件、历史审批及快照。历史 Excel 的网页内容预览仍最多显示每张表前 500 行和 40 列，完整内容应下载原文件查看；新增或替换报价文件不再接受 Excel。
- 页面文件选择、保存前检查、未保存附件预览与服务端归档统一只接收 DOCX，继续校验大小、MIME 和 OOXML 真实结构。Excel、PDF 等改名为 DOCX 也不能通过。客户等其他模块的通用附件格式不受此次报价限制影响。
