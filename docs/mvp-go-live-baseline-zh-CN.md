# MVP 正式上线范围基线

原基线日期：2026-10-14。本文归档当时拟定的完整试运行范围。2026-11-10 的实际外网首发采用 `CORE`，交付范围、现行报价流程及部署验收以 [外网部署交接文档](external-deployment-handoff-zh-CN.md) 和 [当前需求](requirements-zh-CN.md) 为准。

## 1. 上线目标

在公司内网为 5 名售前及少量领导提供一套可实际录入真实业务数据的系统。第一版优先保证客户数据隔离、过程留痕、提醒、调研、报价三级审批、合同固定正文与附件一致性、备份恢复和可编辑 Word 导出；不以扩展功能阻塞上线。

## 2. 第一版必须完成

| 范围 | 上线最低标准 |
|---|---|
| 账号与权限 | 独立账号；售前只访问本人客户；转让后原负责人立即失权；研发经理、综合部经理和副总经理仅按管理或审批职责访问；管理员重置后强制改密 |
| 客户与跟进 | 客户主档、联系人、跟进时间线、客户状态、负责人转让、操作留痕；历史 Excel 经预览、人工匹配和逐项确认导入 |
| 提醒 | 本人创建或部门负责人及以上指派；铃铛为统一入口；无法完成、关闭、恢复、重新指派均留痕 |
| 区域与地图 | 第一版允许先以权限化清单展示每人负责区域和客户分布，不绘制来源不明边界或推测点位；取得来源明确、审图号可核验的中国标准地图原图后自动启用点位叠加 |
| 软件调研 | 草稿、问题答案、清单、完成确认、修改原因、重新确认、可编辑 Word；完成版附件使用固定版本 |
| 报价 | 创建后显示“未发送”；客户名称在报价单内填写，联系人自动取创建人手机和邮箱；创建时仅可上传 Word（DOCX）；服务端计算、历史版本、研发经理—综合部经理—副总经理三级审批、每级审核人/时间/备注、退回后新版本、终审快照、可编辑 Word |
| 合同 | 正文不改；仅白名单业务槽位和附件一可变；异构报价无法安全映射正文唯一明细行时严格拒绝；生成、外部编辑归档、最终签署及关键差异门禁完整留痕 |
| 通用附件 | 客户、跟进、调研及问题、未发送报价可上传、替换、下载和受控删除；新增及替换报价文件只接受 Word（DOCX），历史文件保留；被调研确认版或报价审批记录引用的版本不可覆盖或删除；全部纳入备份 |
| 表单防丢 | 调研和合同草稿、未发送报价显示未保存/保存中/已保存/失败；自动保存不自动完成、发送审批或生成合同 |
| 运维 | 内网 HTTPS、专用运行账号、开机自启、正式库和附件目录、每日备份、失败可见、隔离恢复演练、升级前备份 |
| 验收 | 四角色走通本机试运行地址；桌面和 390×844 关键路径；当前生产合同候选完成管理员发布及代表性生成回读；真实 Excel 迁移对账；控制台无关键错误 |

## 3. 明确不阻塞第一版上线

以下内容保留为上线后迭代，不再作为第一版发布关口：

- 用户头像、个性化主题、复杂个人资料页。
- 全局审计搜索、分页、批量导出和独立审计中心；第一版只要求规定动作可靠留痕并能在业务对象中查看。
- 地址自动地理编码、在线地图服务、路线规划和动态行政区划；第一版采用经业务确认的离线底图与人工点位。
- 通用异步导出任务中心、导出进度队列和外部消息通知。
- 联系人附件、合同附件一之外的新附件类型、跨客户共享资料库。
- 客户“协同人员”自动获得访问权限；继续执行“仅负责人可访问，转让后变更权限”的已确认规则。
- 自动免费额度或独立免费服务模块；继续执行 SOP 的逐项书面审批，涉及报价或合同变化时仍走原审批链。
- 培训、学习、改善类 Excel 工作表自动转业务记录；未明确映射的历史内容只保留来源，不自动生成跟进、提醒、报价或合同。
- 公网、客户门户、外部用户、自助注册、移动 App 和多公司租户。

## 4. 四个会话的统一结论

- 项目经理会话负责范围、上线关口、验收和问题汇总，主仓库是唯一交付依据。
- 代码开发会话的阶段性成果已合入主仓库；其旧工作树或失败任务不作为更新来源，不重复实现已经合入的批次。
- 合同模板适配成果已合入主仓库。当前保留严格口径：正文汇总行只有在单位、未税单价和税率一致时才合并数量；否则拒绝生成并要求使用可承载该报价的新版模板。
- 原型设计只用于页面结构和操作路径参考；模拟数据、模拟自动保存或浏览器本地状态均不算正式功能。

## 5. 从现在起的执行顺序

1. 通用附件已完成页面入口、旧库迁移、权限、快照、备份恢复和全量回归。
2. 长表单草稿自动保存已完成服务端版本令牌、失败提示、离页提醒和审批边界验证。
3. 当前按本文逐项做代码差距复核，只修第一版范围内的真实缺口；冻结新功能。
4. 先用区域与客户分布清单投入本机验收；正式地图资源后补。按用户 2026-10-14 对当前候选的确认，由管理员上传、复核门禁并发布生产合同模板。
5. 在隔离验收库建立正式角色和负责人映射，以真实 Excel 做预览、核对、试迁移和对账，不直接写正式库。
6. 在当前 Windows 电脑完成本机部署、备份及隔离恢复演练；多人内网访问、HTTPS 和开机自启作为从本机试运行扩展到五人共用前的独立运维关口。
7. 四角色按正式地址完成业务验收；通过后再启用真实生产库。

## 6. 需要用户或运维提供的最小输入

开发工作可以先继续；以下信息在对应发布关口前必须提供：

1. 首次管理员用户名、显示名称和由用户本人在终端隐式输入的密码；不要在对话中发送密码。
2. 正式账号清单：姓名/显示名、角色、售前所属部门负责人；以及现有客户到售前负责人的映射。可在迁移前提供，不应提交到 Git。
3. 如后续启用真实地图，再由管理员从自然资源部标准地图服务取得原图、审图号和来源页面；当前清单模式不因此阻塞本机试运行。

## 7. 上线判定

只有代码全量回归、地图清单模式与合同模板发布验收、当前电脑备份恢复、真实数据试迁移对账和四角色 UAT 均留有证据后，才能把状态改为“可正式使用”。正式中国地图原图已明确后补，不再阻塞清单模式试运行；本地测试通过、文件生成成功或原型可点击，仍不能单独替代业务验收。
